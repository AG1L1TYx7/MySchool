# SmartSchool Design Documentation

**Status:** current as of 2 October 2026. This folder is the canonical design documentation for SmartSchool and the starting point of the build.

## What SmartSchool is

An AI-native K-12 learning management system for US schools and districts that runs entirely on infrastructure the school controls. A complete LMS (rostering from the school's student information system, classes, assignments, grades, attendance, messaging, parents, private gamification, district administration) is paired with an AI service that uses local language models through Ollama to tutor students without doing their work, generate teacher-reviewed interactive content, grade with teacher confirmation and surface where a class is stuck. Emotion detection, public leaderboards, betting-style stakes and recruiter access are excluded by decision (ADR-024). What makes it outstanding, and the bar every release must meet, is in [08-PRODUCT-STRATEGY.md](08-PRODUCT-STRATEGY.md).

## Reading order

New to the project: 08, then 01, then 07.
Building a slice: 07 for the slice, 09 for the routes, 02 for the behaviour, 03 for the tables, 04 if it crosses a service boundary, 10 for anything AI, 12 for every screen, 13 for anything a school or district will evaluate, and 11 before calling it done.
Reviewing a design change: 05 first, then the affected section of 01.

## Conventions

- **Previous implementation** means the C# API and Python AI service in the old repository. **Target** means `apps/api`, `apps/web` and the retained `apps/ai`.
- Status labels in the feature catalog describe the previous implementation: **Real**, **Partial**, **Stub**. Every stub is listed so it is not rebuilt as a stub (ADR-008).
- Diagrams are Mermaid and render on GitHub and in most editors.

## Regenerating the endpoint inventory

From a clone of the old repository:

```powershell
node docs/tools/extract-routes.cjs <clone>/SmartSchool.Api/Controllers <clone>/SmartSchool.AI/main.py > docs/06-ENDPOINT-INVENTORY.md
```

Summary counts, verified on 30 September 2026: 77 controllers, 1,126 LMS routes; 155 AI service routes.
